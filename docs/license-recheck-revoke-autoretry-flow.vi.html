LicenseCore SDK · Vận hành sau khi activate

Luồng recheck, revoke, và tự phục hồi license

Sau khi license đã activate lần đầu, điều gì giữ cho trạng thái license luôn đúng với server? Trang này mô tả vòng lặp recheck nền, cách revoke được phát hiện, và tính năng tự động activate lại khi license khả dụng trở lại — không cần restart app.

Đối chiếu với mã nguồn thật skytransporter/TransporterAgent, skylicense-core-sdk/core/src/commonMain và skyapp-api ngày 2026-10-16. Tên field/hàm giữ nguyên tiếng Anh để khớp mã nguồn.

iBa thành phần liên quan

ⓘ
Ai làm gì TransporterAgent (C#, Windows Service) là app thật dùng SDK — nó quyết định khi nào gọi activate, đọc config, chặn HTTP request khi license không hợp lệ. skylicense-core-sdk (Kotlin/Native, biên dịch ra licensecore.dll) chứa toàn bộ logic verify/cache/recheck — chạy hoàn toàn độc lập, không biết gì về nghiệp vụ của app. skyapp-api là nguồn sự thật duy nhất về trạng thái license — mọi quyết định cuối cùng (còn hạn, bị revoke, còn slot) đều do nó trả lời.

⇄Luồng tổng thể

Một chu kỳ đầy đủ: activate thành công, recheck giữ token, admin revoke, agent phát hiện và tự phục hồi.

sequenceDiagram participant T as TransporterAgent participant K as skylicense-core-sdk participant S as skyapp-api T->>K: InitializeAsync + ActivateAsync(licenseKey) K->>S: POST /verify S-->>K: JWT đã ký (ES256) + checkIntervalMinutes K-->>T: state = VALID Note over T,K: LicenseGateMiddleware mở cổng HTTP loop Mỗi checkIntervalMinutes K->>S: POST /token/introspect S-->>K: isRevoked=false K-->>T: vẫn VALID (giữ token cũ) end Note over S: Admin revoke license
RevokeAllForLicense() đánh dấu token IsRevoked=1 K->>S: POST /token/introspect (tick kế tiếp) S-->>K: isRevoked=true K-->>T: state = Unlicensed, cache bị xoá Note over T: LicenseGateMiddleware chặn HTTP (503) Note over S: Admin reactivate license loop Mỗi RetryActivationIntervalMinutes (timer mới, phía T) T->>K: ActivateAsync(licenseKey) lại K->>S: POST /verify end S-->>K: JWT mới (license đã Active) K-->>T: state = VALID Note over T,K: Middleware tự mở lại - không cần restart

DAuto-retry activate mới thêm

Khoảng trống quan trọng: licensecore.dll chỉ verify lại token đã có trong cache — không bao giờ tự thử activate lại khi cache rỗng, kể cả khi license khả dụng trở lại.

⚠
Vấn đề gốc Sau khi license bị revoke và cache bị xoá, admin reactivate license xong — nhưng app đang chạy vẫn kẹt mãi ở Unlicensed. Không có restart thì không bao giờ tự phục hồi, vì checkNow() chỉ làm 2 việc: verify token cache cũ, hoặc publish thẳng Unlicensed nếu cache trống — không có nhánh "thử activate lại".
1Timer độc lập phía appTTransporterAgent

Thêm System.Threading.Timer trong LicenseHostedService, tick mỗi RetryActivationIntervalMinutes (mặc định 5 phút) — hoàn toàn tách biệt khỏi scheduler nội bộ của DLL.

LicenseHostedService.cs (OnRetryActivationTick)

✎Thao tác người dùng cần làm

Toàn bộ luồng ở trên tự chạy — đây là những điểm duy nhất cần con người can thiệp.

✓
Vận hành bình thường Không cần làm gì — activate, recheck, phát hiện revoke, tự phục hồi đều tự động.

Khi admin muốn revoke license

Gọi POST /api/licenses/{id}/revoke (cần session admin đăng nhập, kèm reason) — agent tự phát hiện trong tối đa 1 chu kỳ checkIntervalMinutes, không cần thao tác gì thêm phía agent.

Khi admin muốn mở lại license đã revoke

Gọi POST /api/licenses/{id}/reactivate — agent tự activate lại trong tối đa RetryActivationIntervalMinutes (mặc định 5 phút), không cần restart.

Nhưng lúc tính hạn token thật, backend lại tra theo (license.BuyerOrganizationId, license.StoreId) — nếu 2 orgId này khác nhau (license thuộc 1 tổ chức, app config 1 orgId khác), chỉnh setting ở orgId của app sẽ không ảnh hưởng gì tới hạn token thật.

Sửa setting thẳng trong DB không có hiệu lực ngay

ISettingService cache giá trị trong RAM của tiến trình backend. Sửa thẳng DB không trigger ClearCacheAsync() — phải gọi lại POST /settings (dù giá trị không đổi) hoặc restart service.

Race condition ký token dưới tải đồng thời (đã sửa)

CryptoProviderFactory của Microsoft.IdentityModel.Tokens mặc định cache SignatureProvider theo key — nhưng code cũ dispose ECDsa ngay sau mỗi lần ký/verify, nên request đồng thời có thể lấy trúng provider đã cache với key bị dispose → ObjectDisposedException ngẫu nhiên (~1/3 request fail khi test). Đã sửa bằng CacheSignatureProviders = false.
